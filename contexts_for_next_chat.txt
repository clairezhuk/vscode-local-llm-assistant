**Project Essence**

A local AI programming assistant built as a VS Code extension.

* **Resources:** Optimized for entry-level hardware (2GB VRAM, 8GB RAM). Utilizes quantized Qwen 2.5 Coder 1.5B via llama.cpp with a restricted context window (2048 `n_ctx`) and reduced batch size (128 `n_batch`) for CUDA stability.
* **Key Features:** Real-time streaming chat, structured multi-step Thinking workflows using KV Cache state saving, non-blocking concurrency management for shared GPU access, and human-in-the-loop terminal execution.
* **VRAM & Context Management:** Solved the 2048 token bottleneck by implementing a prioritized context stack and utilizing native `llama.cpp` KV Cache state saving. This allows for complex, multi-step reasoning without evicting the original file context or query from memory.

---

**Class Responsibilities**

**Frontend (VS Code Extension - TypeScript):**

* **`chat_view.ts` (ChatViewProvider):** Manages the Webview UI. Implements JSON-stream buffering (protection against fragmented chunks), passes the workspace directory path to the backend, and handles the `AbortController` for safe generation interruption.
* **`ghost_text.ts` (GhostTextProvider):** Provides inline code completions. Operates via the backend's request queue, functioning alongside the chat.
* **`Webview Script`:** Handles real-time markdown rendering and interactive UI elements like Accept/Reject buttons for terminal commands.

**Backend (FastAPI - Python):**

* **`engine/llm.py` (LLMEngine):** The core engine wrapper for `llama.cpp`. Manages the 2048 context window, exposes C-API methods for KV state saving/loading (`save_state`/`load_state`), and utilizes an internal `asyncio.Lock` with thread delegation to prevent FastAPI event loop blocking during concurrent VRAM access.
* **`agentic_orchestrator/orchestrator.py` (Orchestrator):** The "Managing Director." Handles the request lifecycle: query preprocessing, file context aggregation, and high-level routing.
* **`agentic_orchestrator/reasoning.py` (ReasoningEngine):** The "Thinker." Implements Fast Mode and Thinking Mode. Orchestrates deterministic, multi-step pipelines (e.g., Extract -> Draft -> Finalize) while manipulating the KV Cache to maintain context. Uses safe asynchronous generators for streaming.
* **`agentic_orchestrator/prompts.py` (PromptLibrary):** A centralized repository for all system instructions. Ensures persona consistency and precise JSON templates for reasoning steps.
* **`context_manager/kv_cache.py` (KVCacheManager):** Manages saving and loading of the model's KV Cache state in RAM. Reuses prefilled context (files, base instructions) across multiple independent reasoning steps to save tokens and execution time.
* **`context_manager/manager.py` (ContextManager):** Implements an intelligent sliding window for dialogue history to strictly enforce character limits and maintain stability.
* **`context_manager/file_processor.py` (FileProcessor):** Smart contextualization system. Performs "Structural Extraction" or "Semantic Summarization" for large files to preserve context within token limits.
* **`executor/tools.py` (ToolExecutor):** Executes terminal commands within the user's specific workspace context, supporting human-in-the-loop verification (Accept/Reject).

---

**Current State**

A highly optimized deterministic Reasoning Pipeline is implemented, replacing heavy self-critique loops to stay within the strict 2048 token limit:

1. **Concurrency & Streaming Safety:** GPU access is protected by an `asyncio.Lock` embedded directly in `LLMEngine`. Streaming utilizes `run_in_executor` with safe generator iteration (catching `StopIteration`) to ensure the FastAPI event loop remains responsive to UI and Ghost Text requests while generating tokens.
2. **Fast Mode:** Direct, single-pass response generation for simple questions and immediate instructions.
3. **Thinking Mode (KV Cache Pipeline):**
* **State Saving:** The base context (system prompts, attached files, workspace) is evaluated once. Its KV Cache is saved to RAM, preventing truncation during complex task resolution.
* **Deterministic Text Pipeline:** Extract Facts -> Draft Solution -> Finalize concise response.
* **Deterministic Code Pipeline:** Define Interface/Signature -> Plan Algorithm -> Write Code.
* **Deterministic Terminal Pipeline:** Analyze Environment -> Generate specific command.
* **Token Efficiency:** Intermediate reasoning steps use tiny, strictly focused prompts layered on top of the saved KV Cache, drastically improving logical accuracy without overloading VRAM.


4. **Robust Streaming:** The frontend utilizes a text buffer to collect fragmented JSON packets, ensuring smooth text rendering even during fluctuating generation speeds.
5. **Safe Terminal:** Commands are generated based on environment constraints, displayed for user verification, and executed strictly within the project's working directory.

Testing System (Benchmarks)

An automated sandbox designed to verify architectural stability and reasoning
quality.

  - Structure: Thematic test suites (Algorithms, CLI, Logic).
  - Runner: Creates isolated temp directories, executes generated code, and
    verifies results via assert statements. Supports real-time CSV logging and
    manual mode selection (fast vs. thinking).
  - Metrics: Focuses on the Self-Correction Success Rate (success after
    retries), processing time.
  - Warning Detection: Automatically detects if the AI output contains a
    "Warning" badge, indicating failed internal verification.
  - Running from Docker

Technical Constraints & Solutions

  - VRAM Limit (2GB): Solved by reducing n_ctx to 2048 and n_batch to 128. This
    prevents "Out of Memory" errors during deep reasoning cycles.
  - Thread Safety: Resolved using asyncio.to_thread for the execution of
    synchronous llama_cpp calls and a global asyncio.Lock within the
    Orchestrator, making the local server stable under parallel requests from VS
    Code.
  - Instruction Adherence: Addressed by strictly limiting tokens in planning
    stages and using specialized system prompts to prevent the 1.5B model from
    looping or repeating instructions.

Data Analysis System

A specialized evaluation pipeline (analysis.py) that transforms benchmark 
CSV logs into a 12-file diagnostic report stored in versioned 
results/analysis/analysis_vN/ folders.

  - 0_text_stats.txt: Detailed log of per-mode performance. Reports 
    Full/Partial test counts, attempt-level success %, Warning Efficiency 
    (Correct Warnings / Total Fails), and Interference (Wrong Warnings / 
    Total Successes).
  - 1_general_heatmap.png: Categorical grid showing pass levels (100%, >50%, 
    Partial, Fail) and self-correction markers. Includes a numeric Y-axis 
    for all test indices, fine-grained grid lines, and a color-coded legend.
  - 2_percentage_heatmap.png: Continuous gradient (Red-Yellow-Green) mapping 
    exact success ratios. Uses NaN-masking to keep cells for non-existent 
    tests black (background color).
  - 3_bars_by_suite.png: Success ratio comparison (0.0–1.0) grouped by 
    test suite blocks (e.g., Algorithms, CLI) using a fixed mode order.
  - 4_bars_by_intent.png: Success ratio comparison segmented by request 
    complexity: Theory (1), Coding (2), and CLI (3).
  - 5_latency_by_mode.png: Boxplots showing processing time (time_s) 
    distribution per mode to identify median speed and VRAM-related outliers.
  - 6_latency_by_suite.png: Segmented boxplots evaluating how different 
    thematic blocks (e.g., Logic vs. Shell) impact generation duration.
  - 7_latency_by_intent.png: Boxplots comparing processing time specifically 
    across Theory, Coding, and CLI tasks.
  - 8_conf_matrix_all.png: Warning Confusion Matrix for all tests. Maps 
    TP (Warn/Fail), TN (NoWarn/Pass), FP (Warn/Pass), and FN (NoWarn/Fail).
  - 9_conf_matrix_coding.png: Specialized Confusion Matrix identical to #8 
    but isolated to Intent 2 (Coding) to measure code-specific critique accuracy.
  - 10_warning_proportions.png: Bi-directional bar chart. Positive Y-axis 
    (Blue-Green) shows Correct Warning rates; negative Y-axis (Orange-Red) 
    shows False Positive (Wrong Warning) rates per suite.
  - 11_response_effectiveness.png: "Model Honesty" chart. Measures the 
    rate of attempts that were either correct OR correctly flagged as wrong 
    by the internal critique logic.

All visualizations strictly follow the hierarchy: 
Fast -> Planning -> Chain of Draft -> Reflection_refine.
